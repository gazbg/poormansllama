One generated token of Qwen3.8-27B (IQ3_XXS) on the GTX 1070, with 32 of the 64 layers streamed through two VRAM slots and the other 32 computed by the CPU. Every bar is a real interval from an nsys capture of your sanity-check command: 806 ms per token, 1.24 tok/s.

Four things run at once

Each unit is busy for a different share of the same 806 ms. They add up to about two seconds of work, so they overlap.

    Two chains that each fill the whole token

    The copy lane is one chain: 32 packages, one after another. The compute is another chain: GPU layer, hand-off, CPU layer, hand-off, next GPU layer, because each layer needs the output of the one before it. Both come to 806 ms here, so moving work from one to the other only moves the limit to the other side.

    Copy chain: 32 weight packages of 155 MiB at 6.46 GB/s
    Compute chain: host layers, GPU layers, everything else

    Moving layers between the two chains

    Streaming fewer layers shortens the copy chain (25 ms per layer) and lengthens the compute chain (about 20 ms per layer). The measured token speed follows whichever chain is longer.

    Compute-chain figures are a fit (20 ms per host layer plus 90 ms fixed, from the 24 and 28 runs), except the 32-layer one, which is read from the capture: the fit would say 730 ms, but the host layers stretch to 22.9 ms when the copy engine never pauses. The 30-layer run was predicted before it was measured and landed within 1%. About 30 streamed layers is the best this scheme reaches, +4% over 32. Measured: 64 greedy tokens after a 670-token prompt, two requests per setting, after a warm-up, no profiler attached. The 32-layer run in this table streamed the odd layers; the capture above streamed the even ones, which have the same size to within 0.5%.
    How the lanes were built. Copy lane: host-to-GPU copies over 1 MiB, six per layer package (11.5, 15.9, 32.5, 36.5, 36.5 and 21.5 MiB). GPU lane: kernels closer than 0.5 ms merged; a cluster of 20 or more kernels is a streamed layer, smaller clusters are the few small operations between layers. CPU lane: the time between the activation copy to the host and the copy back (20,480 bytes each), which is when the host layer runs; it is not a CPU profile. Blocked lane: the main thread inside cudaStreamSynchronize or cudaEventSynchronize for more than 0.2 ms. Not shown. Which layer each package and burst belongs to is inferred from order (the n-th burst after a token boundary is layer 2n); nsys has no layer labels here. One token (the fourth from the end of the capture) is drawn; the other 47 look alike.
