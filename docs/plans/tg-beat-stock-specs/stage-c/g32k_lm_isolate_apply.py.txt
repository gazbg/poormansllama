The layer-major pass takes one sequence per batch. When two clients are active the server mixes the generating slots' tokens (and the other slot's prompt chunk) into the same llama_decode batch as the big prompt chunk, so the pass declines and the
window serves it. The mix does not buy the other slots anything while a multi-second prompt batch runs (their decode advances one token per batch either way), so the iterations are re-ordered:
  - a PROMPT TURN carries only the first slot whose remaining prompt is >= --lm-prefill-min tokens (the generating slots' tokens wait one iteration);

  - while some slot is generating the two turns alternate, so a generating slot still gets one token per big prompt batch, as before; without a generating slot the prompt turn repeats.
If a prompt turn ends with an empty batch (the big chunk could not add tokens) the generating slots' tokens are added after all, so that the batch is never empty while work is pending.
