Measured (g94-sc24, g94-sp24, certified): with a 24-token prompt on the stock graph path the prefill takes 419 ms without MTP and 468 ms with it (+48 ms = -10.4% PP), for ONE draft decode of 24 rows; the same
catch-up costs 19 ms per 512 rows once the draft graph is warm (g94-lc4k: 8 calls in 154 ms). The difference is first-use cost (graph build, kernel module loads) that is paid inside the first catch-up decode, i.e. inside the

after it is created and drops it again, so the first real catch-up finds a warm context. The draft KV is emptied by seq_rm before the prefill starts: no state is left behind.

                n_layer, n_embd_out, (unsigned) cparams.n_rs_seq);

                n_layer, n_embd_out, (unsigned) cparams.n_rs_seq);
        {
            // G30: warm-up decode of the draft context (see stage-c/g30d_draft_warmup_apply.py.txt): first-use costs are paid here, not in the timed prefill
            const int64_t t_w0 = ggml_time_us();
            const int n_w = std::max(1, std::min(mtp_catchup, ubatch));
            llama_batch wb = llama_batch_init(n_w, n_embd_out, 1);
            wb.token = (llama_token *) malloc(sizeof(llama_token) * (size_t) n_w);
            if (wb.token != nullptr) {
                for (int i = 0; i < n_w; ++i) {
                    wb.token[i]      = 0;
                    wb.pos[i]        = i;
                    wb.n_seq_id[i]   = 1;
                    wb.seq_id[i][0]  = 0;
                    wb.logits[i]     = false;

            }
            llama_batch_free(wb);
