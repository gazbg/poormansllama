"""G32e: --lm-prefill-ckpt-chunk N. The stock server cuts the last 4 + n_ubatch tokens of a prompt into their own batches so that two context checkpoints exist at the end of the prompt (before the 512-token chunk and before the last 4
tokens). On this model the 512-token chunk goes through the ordinary path (not a layer-major pass: it is below --lm-prefill-min), where it copies all expert banks: ~1.3 s per request (g620: 4k prompt 3.96 s = pass 2.0 + chunk 1.3 + cache 0.6).
A chunk of fewer than 32 tokens is computed on the CPU by the stock path (no bank copy). With --lm-prefill the checkpoint chunk can therefore be made small: the checkpoint before it is then taken N + 4 tokens before the end of the prompt
instead of 4 + n_ubatch (a rollback deeper than that falls back to the next older checkpoint). Default 0 = the stock rule (nothing changes).
Also: the default of --lm-prefill-min becomes 1024 (g630, cold prompts, 3 repetitions: min 2048 / 1024 / 512 / 256 give 3.91 / 3.55 / 4.06 / 4.09 s for 2,047 tokens and 2.45 / 2.45 / 3.35 / 3.65 s for 1,024 tokens: a pass
below ~1,000 tokens costs more than the ordinary path, and a minimum of 512 or less also takes the 512-token checkpoint chunk into a pass of its own)."""
