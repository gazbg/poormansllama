"""G31s: seed the expert cache's popularity from the routing of the PROMPT's last tokens (the cold-start penalty).
Measured: the first 128 tokens after a fresh prefill decode 10-15% slower than a repeat of the same prompt (g336/g337: 24,000 tokens cold 87-89 t/s, warm 96-98 t/s = 2.86-2.92x against 3.0x warm), because the cache holds the
experts of the PREVIOUS conversation and the promotion budget (16 per step) needs ~100 tokens to adapt. The prompt tells which experts the next tokens will want: when a decode of 17 .. min_tokens-1 tokens runs (the 516-token
checkpoint chunk the server cuts before the end of a prompt), an evaluation callback reads the router's top-k of its last K tokens (the nodes `ffn_moe_topk-<layer>`, a few hundred KB per layer, one sync per layer) and at the
next decode of <= 16 tokens (before the window closes and the cache is refilled, and before the first generated token) the engine folds them into its EMA exactly as K decoded tokens would have:
ema = lambda^K * ema + sum_r (1-lambda) lambda^(K-1-r) [selected in row r]. Server only (registered by llama_hybrid_set_seed), K = --hybrid-moe-seed (default 32, 0 = off).
Also: the start slack of the server's cache sizing defaults to 128 MiB instead of 512 (the slack above the margin that a window or a KV commit does not need: measured g360 +4.5% TG at 24k cold, watcher minimum unchanged)."""

    const double decay = 1.0 - lambda;
    double scale = 1.0;
    for (int r = 0; r < K; ++r) {
        scale *= lambda;
    }

        v *= scale;
    }

static void hybrid_decode_hook(llama_context * ctx, int32_t n_tokens) {
