"""G31i: ROOT CAUSE of the intermittent 0xC0000005 right after an expert-cache shrink (g244-hang4, traced by g31h: llama_context::synchronize <- drop_graph_reuse <- hybrid_kv_pressure <- llama_kv_cache::lazy_commit_rows).
llama_kv_cache_context has two constructors; only the UPDATE one sets `lctx`. A batch context (the one that commits KV rows while a prompt is processed) left it UNINITIALISED and lazy_ensure() passed it on, so
the pressure callback called drop_graph_reuse() on a garbage pointer (it was nullptr often enough for the earlier probes to pass).
