"""G32i (after the decline reasons of g840/g841): two changes that make the layer-major pass fit the common -np 2 pattern, a conversation per slot taking turns.

The g32h diagnostics showed WHY the second turn of a conversation was declined at -np 2:
  - default cache (--cache-ram 8192, unified KV): when a task switches slots the server restores the prompt from the host cache into the slot while the previous slot still holds its cells (they are saved and cleared only
    AFTER the task is launched), so the restored sequence is scattered around those cells: "the block starting at cell 518 breaks at cell 24042 (empty ...)".
  - --cache-ram 0 (idle slots keep their cells): a fresh conversation was placed right behind the first one, so the first one had no room behind its block on its next turn: "the room behind the block (cells 24000 ..) is taken at cell 24051".
Changes:
  1. server (only with --lm-prefill, unified KV and idle-slot caching): before the prompt is restored into the selected slot, the OTHER idle slots are saved to the host cache and cleared -- which the server does right after the
     launch anyway -- so the restore lands in an emptier cache, as one contiguous block.
  2. llama_kv_cache::lm_block, fresh sequence: prefer a place with a gap of H = min(16384, size/16) cells in front of it (room for the left neighbour to grow into) and H empty cells behind it; fall back to the first run that fits.
Edits: tools/server/server-context.cpp, src/llama-kv-cache.cpp."""
